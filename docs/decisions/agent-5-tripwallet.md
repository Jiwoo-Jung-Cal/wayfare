# TripWallet milestone 1 decisions

- Reuse shared repository, schemas, integer-money helpers, clock and shell registration. No shared platform changes.
- Cash claim identity is `(actionRecordId, recoveryComponentId)` through `ensureClaims`; existing claims and allocations are never rewritten by sync. Successful simulated actions are labeled simulated; failed/pending actions are excluded. Noncash components never become cash claims; issuing new noncash assets from actions is deferred.
- Expected, provider-confirmed, received and outstanding are overlapping stages, never additive columns. Outstanding uses provider-confirmed when known, otherwise expected. A lower promise preserves original expectation and shows needs-review; negative outstanding after a changed promise remains visible, not clamped.
- Status: expected -> provider_confirmed -> partially_received -> received, with needs_review for differing promises/over-receipt. Overdue is an independent active-clock flag (`now >= sourced due date` and unpaid balance); unknown due date stays unknown.
- Receipt source reference is unique through shared putReceipt. Allocate one full receipt to one cash claim in this MVP; multiple distinct receipts can reconcile one claim. Matching proposals require booking reference, merchant, currency, positive amount within balance and posting no earlier than action/claim creation; ambiguous matches always require review. All allocations require a user selection, including a unique suggestion. No amount-only match.
- Allocations are the authoritative match ledger. Avoid a second saveReceipt write that could fail after saveClaim; UI derives matched status from allocations. Optimistic revision protects same-claim contention. **Cross-claim concurrent allocation is not atomic in the current shared repository**: Agent 1 request posted on #3. Do not claim concurrency-safe final acceptance yet.
- Evidence is saved verbatim with hash before reconciliation. User-reviewed form supports arbitrary pasted evidence; sample buttons prefill canonical fictional inputs. No wallet AI endpoint exists in FeatureContext v1; requested Agent 1 wiring. No live AI or external provider call is claimed.
- Assets display their native money/points units, issuer, source-document reference, restrictions and expiry. Free-text restrictions cannot safely authorize automatic redemption; assetEligibility conservatively returns a review reason. Reservation, redemption, structured eligibility rules and grouped eligibility integration remain future milestone work.
- Functional shared-component UI only. Jiwoo's TripWallet visual approval/revision is pending. Do not treat this as visual acceptance.
- Direct git clone was attempted but CLI credentials were missing. Source was materialized through authenticated GitHub connector at pinned main f3a10dd; changes published using Git trees/commits with a fast-forward-only, expected-head update on the assigned branch. No files outside Agent 5 ownership changed.
